# Android 소규모 베타 관찰

한국어로 짧은 일기를 남기고 싶은 Android 사용자가 첫 기록을 시작하고 쉬었다가 돌아올 수 있는지 살펴봅니다. 모집 기준은 제품 가설이며 적합한 타깃이나 심리 효과를 검증한 사실이 아닙니다. 5~10명을 모집하는 계획으로 시작하고 실제 참여 인원은 별도로 기록합니다. 새 네트워크 추적이나 일기 본문 수집은 추가하지 않습니다.

## 설치와 데이터 한계

2026-10-11 확인한 공개 v1.2.3에는 AAB만 있어 직접 설치 가능한 APK가 없습니다. 서명된 `app-release.apk`가 실제 GitHub Release 첨부에 나타난 뒤 모집과 설치를 시작합니다. [릴리스 가이드](RELEASE.md)의 소스 구현과 외부 게시 상태를 구분하세요. Play 등록은 별도 절차입니다.

APK 업데이트는 같은 서명이 필요합니다. 설치 오류를 앱 삭제로 해결하지 않습니다. 먼저 완료 기록 JSON 텍스트를 내보내고 복원 범위를 확인합니다. 사진, 초안, 설정은 JSON 백업에 포함되지 않으며, 기존 기기의 사진 파일이 새 기기에서 복구된다고 약속하지 않습니다. 테스트에는 참가자가 고른 비민감 예시나 가상 기록을 권합니다.

## 네 가지 시나리오

| 시나리오 | 시도한 사람 | 성공 기준 | 실패 또는 미관찰 |
| --- | --- | --- | --- |
| 첫 기록 | 설치 후 첫 기록 화면에 진입한 사람 | 감정과 답변 하나 이상으로 저장하고 타임라인에서 기록 확인 | 저장 실패, 저장 뒤 기록 없음, 중단 |
| 쉰 뒤 재방문 | 첫 기록 후 합의한 3일 이상 쉬고 다시 연 사람 | 이전 기록을 확인하고 새 기록을 저장 | 이전 기록 없음, 새 저장 실패. 아직 돌아오지 않은 사람은 미관찰로 별도 집계 |
| 재시작 초안 복구 | 비민감 답변을 입력하고 앱을 종료한 사람 | 앱 재시작 후 완료하지 않은 답변을 그대로 확인하고 저장 | 초안 유실, 이전 완료 기록 덮어쓰기 |
| JSON 텍스트 복원 | 완료 기록 JSON을 내보내고 별도 테스트 설치/기기에서 가져오기를 시작한 사람 | 날짜, 감정, 답변 텍스트가 일치하는 완료 기록 확인 | 파일 읽기/복원 실패, 텍스트 불일치. 사진 복구는 성공 조건이 아님 |

복원 시험은 실제 기록을 지우지 않는 별도 환경에서 진행합니다. 취소나 실패 때 기존 기록이 그대로 남는지도 참가자가 확인합니다. 앱 강제종료 초안 시험은 본인의 선택으로 진행하고 대기한 시간과 종료 방식을 함께 기록합니다.

## 분모와 관찰 기록

각 시나리오별로 `시도한 사람 수`, `완료한 사람 수`, `실패한 사람 수`, `중단한 사람 수`, `미관찰 수`를 따로 기록합니다. 성공률은 완료한 사람 수 / 시도한 사람 수이며, 모집 인원이나 설치 인원으로 바꾸지 않습니다. 한 사람의 여러 시도는 사람 기준 성공률에 중복 산입하지 않고 시도 횟수는 별도 열에 기록합니다. 재방문은 대상 인원, 관찰 가능한 인원, 실제 재방문 인원을 각각 기록하여 돌아온 사람만의 성공률을 전체 재방문율로 표현하지 않습니다.

측정할 항목은 앱 버전, Android 버전, 시나리오, 시작/끝 시각, 성공 상태와 오류 종류입니다. 첫 기록 소요시간은 화면 진입부터 저장 확인까지 측정할 계획이며 30초는 가설일 뿐입니다. 아직 실측값이 없습니다. 실패와 중단의 시간도 구분해서 남깁니다.

참가자는 화면 공유나 결과 확인을 직접 통제하고 언제든 멈출 수 있습니다. 일기 본문, 사진, JSON 원본, 인증 정보는 제출하지 않습니다. 관찰자는 비민감 예시 기록이나 성공 상태만 보고 필요한 경우 참가자가 가린 화면을 사용합니다. 의견은 참가자가 동의한 익명 요약으로 남기고 보관 기간도 모집 전에 정합니다.
