# UI/UX·접근성·플랫폼 일관성 개선 설계

## 목적

3Lines의 핵심 30초 기록 루프를 유지하면서 경쟁 저널·명상 앱과 플랫폼 접근성
가이드를 기준으로 출시 전 사용자 경험을 재감사한다. 이번 루프는 스키마를
확장하는 기능 추가보다, 이미 존재하는 화면의 신뢰성·접근성·배터리 비용을
측정 가능한 회귀 테스트로 고정하는 데 집중한다.

## 조사 결과

## 발견된 근본 원인

1. `ThreeLinesApp.builder`가 레이아웃 오버플로를 피하려고 `TextScaler`를 1.3배로
   잘라 플랫폼 접근성 설정을 차단한다. 큰 글자에서 발생할 수 있는 문제를
   레이아웃으로 해결하지 않고 입력을 제한한 것이다.
2. `HeatmapGrid`의 `tapSize`가 시각적 셀 크기(최대 20px)에 맞춰져 있어
   `Semantics` 라벨은 있지만 실제 손가락 조작 영역은 Android/iOS 권장치보다
   작다.
3. `RefreshIndicator.onRefresh`가 provider를 무효화만 하고 Future를 기다리지
   않아 로딩 완료와 사용자 피드백의 생명주기가 분리되어 있다.
4. Android 위젯만 저장 날짜와 오늘 날짜를 비교한다. iOS `loadEntry`는 공유
   저장소의 완료 플래그를 날짜와 무관하게 읽는다.
5. `SettingsController.exportData`가 앱 버전을 하드코딩해 앱 업데이트 후에도
   내보내기 파일이 오래된 버전으로 표시된다.

## 설계

### 1. 접근성 우선 레이아웃

- 앱은 플랫폼이 제공한 `MediaQuery.textScaler`를 그대로 전달한다.
- 화면은 세로 스크롤을 유지하고, 히트맵의 시각 셀은 작게 유지하되 각 셀의
  상호작용 컨테이너는 48dp 정사각형으로 분리한다.
- Android/iOS 탭 타깃 및 라벨 가이드 테스트와 200% 텍스트 스케일 핵심 흐름
  위젯 테스트를 추가한다.

### 2. 새로고침 계약

Timeline/Insights의 `RefreshIndicator`는 `ref.refresh(provider.future)`를
await한다. 따라서 스피너가 실제 DB 조회 완료까지 유지되고, 실패 시 기존
에러 화면 계약을 그대로 사용한다.

### 3. 위젯 날짜 정규화

iOS 위젯에 저장 날짜와 `Calendar.current`의 현지 날짜가 같은지 확인하는 순수
정규화 함수를 추가한다. 날짜가 다르면 완료/감정 상태를 미작성 기본 상태로
재설정하고, Android의 기존 정규화와 같은 문구를 사용한다.

### 4. 데이터 메타데이터

내보내기 시 `PackageInfo.fromPlatform()`으로 실제 버전을 읽고, 플랫폼 조회가
실패하면 현재 Settings 상태의 버전 또는 `unknown`을 사용한다. 데이터 포맷과
저장 스키마는 변경하지 않는다.

## 비범위 및 후속 백로그

- 태그/즐겨찾기/다중 저널, 아침·저녁 다중 리마인더, 오디오·가이드 명상,
  클라우드 동기화는 데이터 모델·콘텐츠·개인정보 정책 결정이 필요하므로
  이번 루프에 포함하지 않는다.
- 실기기 배터리 수치와 알림 도착 지연은 연결된 Android/iOS 기기에서 별도
  프로파일링해야 하며, 자동화 테스트 통과만으로 달성으로 표시하지 않는다.

## 검증 기준

- 변경 대상 테스트가 수정 전 실패하고 수정 후 통과한다.
- `flutter analyze` 오류 0개, 전체 `flutter test` 통과.
- 접근성 가이드 테스트에서 Android/iOS 탭 타깃과 라벨 위반 0건.
- Android arm64 릴리스 APK 빌드 통과 및 release manifest에 INTERNET 권한 없음.
- iOS 위젯 소스가 Swift 문법/타깃 빌드 검사를 통과하거나, 환경상 빌드가
  불가능하면 그 한계를 명시한다.
