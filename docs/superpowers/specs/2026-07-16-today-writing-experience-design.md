# Today 작성 경험 개선 설계

## 목표

Today 화면에서 저장 조건과 작성 진행 상태를 즉시 이해할 수 있게 하고, 기존 기록을 수정하다가 취소하면 저장된 원본으로 안전하게 돌아갈 수 있게 한다.

## 범위

- 저장 조건은 현재 규칙인 `감정 1개 + 비어 있지 않은 답변 1개 이상`을 유지한다.
- 저장 버튼 영역에 현재 필요한 다음 행동을 한 문장으로 표시한다.
- 답변 진행 상태를 `작성한 답변 수/3`으로 표시한다.
- 완료된 기록의 편집 모드에는 `취소` 명령을 제공한다.
- 편집 취소 시 감정, 답변 3개, 사진을 `existingEntry` 값으로 복원하고 편집 모드를 종료한다.
- 편집 중 새로 첨부한 미저장 사진은 취소 시 파일에서 삭제한다. DB에 저장된 기존 사진은 삭제하지 않는다.
- 새 기록 작성 중에는 취소 명령을 표시하지 않는다.

## 상태 모델

`TodayState`가 화면에 필요한 파생 상태를 계산한다.

- `filledAnswerCount`: 공백만 있는 답변을 제외한 작성 답변 수, 범위 0부터 3까지.
- `saveGuidanceMessage`:
  - 감정 미선택: `오늘의 감정을 먼저 골라주세요`
  - 감정 선택, 답변 없음: `한 줄만 적어도 저장할 수 있어요`
  - 저장 가능: `저장할 준비가 됐어요`

화면과 저장 버튼은 답변 문자열을 다시 해석하지 않고 이 파생 상태를 사용한다.

## 화면 구성

`AnimatedSaveButton`은 안내 문구와 진행 링, 저장 버튼을 하나의 의미 단위로 렌더링한다. 진행 링 중앙에는 단일 숫자 대신 `n/3`을 표시하고 접근성 레이블에도 같은 진행 정보를 제공한다. 상태 변화는 기존의 짧은 `AnimatedSwitcher`/`AnimatedContainer` 전환만 사용하며 추가 장식 애니메이션은 만들지 않는다.

완료된 기록을 편집할 때 하단에는 저장 영역 아래에 아이콘과 텍스트가 있는 `수정 취소` 버튼을 표시한다. 취소는 파괴적 작업이 아니므로 확인 대화상자를 띄우지 않고 즉시 원본을 복원한다.

## 컨트롤러 흐름

`cancelEdit()`은 완료된 기존 기록을 편집 중이고 저장 중이 아닐 때만 동작한다. 취소를 시작하면 즉시 `isCancelling`을 설정해 저장과 모든 편집 입력을 막는다. 저장 중에도 같은 입력 잠금을 적용해 저장 스냅샷과 이후 편집·사진 변경이 충돌하지 않게 한다. 현재 사진이 DB에 저장된 사진과 다르면 미저장 파일을 먼저 삭제하고, `existingEntry`의 감정/답변/사진을 상태에 복사한 뒤 `isEditing`을 `false`로 설정한다. 저장된 엔트리가 없거나 편집 중이 아니거나 저장 중이거나 이미 취소 중이면 아무 작업도 하지 않는다.

`toggleEdit()`은 기존 호출 호환성을 유지하되 화면에서 편집 종료 용도로 사용하지 않는다. 편집 종료는 의미가 분명한 `cancelEdit()` 또는 `save()`만 담당한다.

## 오류와 비동기 처리

사진 삭제는 `Future`로 기다린다. 사진 서비스는 기존 best-effort 정책을 따라 실패를 기록하고, 앱 시작 시 고아 사진 정리로 복구한다. 예외를 전파하는 서비스 구현에서는 상태 복원을 중단하고 현재 편집 상태를 유지한다. 저장 실패 동작과 저장 조건은 변경하지 않는다.

## 테스트

- `TodayState` 단위 테스트로 안내 문구, 공백 처리, 답변 수를 검증한다.
- `AnimatedSaveButton` 위젯 테스트로 안내 문구, `n/3` 표시, 접근성 및 저장 가능 상태를 검증한다.
- `TodayController` 단위 테스트로 취소 복원, 새 사진 삭제, 기존 사진 보존, 무효 호출, 저장 중 취소 차단, 취소 중 편집 및 저장 차단, 저장 중 편집·사진 변경 차단을 검증한다.
- Today 기능 테스트 전체와 `flutter analyze`를 최종 실행한다.

## 제외 사항

- 자동 임시 저장, 실행 취소 스낵바, 프롬프트 변경, 데이터베이스 스키마 변경은 포함하지 않는다.
- Timeline 및 Insights 화면은 이번 설계에서 변경하지 않는다.
