# 털어놓을 곳이 필요한 순간의 3Lines

2026-11-06. 사용자는 ‘심리적으로 힘들지만 털어놓을 곳이 없어 답답할 때, 이야기를 들어줄 수 있는 공간’을 원한다고 구체화했다. 앞선 [부담을 낮추는 경험](2026-11-06-supportive-journaling-design.md)과 [감정만 기록하기/책갈피](2026-11-06-gentle-features-design.md)에 이어 작성 경험을 조정한다.

## 이번에 반영할 작은 변경

- 작성 첫 화면에서 잘 정리하거나 짧게 줄여야 한다는 압박을 줄인다. ‘여기에 꺼내놓아도 괜찮아요’, ‘말하지 못했던 이야기, 정리되지 않은 마음도 괜찮아요’를 안내한다.
- 기본 첫 질문은 작은 일상 관찰에서 ‘지금 꺼내놓고 싶은 이야기가 있나요?’와 같은 열린 질문으로 바꾼다. 시작 예시는 완성된 감정을 대신 적지 않고 ‘사실 오늘은’ 같은 문장 시작을 제공한다. 사용자 지정 질문과 저장된 질문 스냅샷은 유지한다.
- 각 입력 칸의 200자 제한과 카운터를 제거하고 문단을 나눌 수 있는 여러 줄 키보드를 사용한다. 입력 칸은 3줄에서 8줄까지 커진 후 내부에서 스크롤한다. 한 줄만 적거나 감정만 남기는 기존 기능도 유지한다.
- 첫 안내와 저장 전 안내를 위 방향에 맞춘다. 저장 성공은 실제 저장 사실을 정확히 알린다.
- 첫 답변 분석 제목은 ‘첫 이야기에 자주 쓴 말’로 바꿔 어려운 이야기를 감사로 분류하지 않는다.
- 긴 글 입력을 허용하면 기존 월간 PDF의 분할 불가능한 일기 카드에서 `TooManyPagesException`이 발생하는 것을 재현했다. 본문을 페이지 사이에 나눠 출력하도록 해당 경로도 함께 수정한다.

별도 모드나 DB 구조를 만들지 않고 기존 세 질문과 답변 필드, Flutter TextField를 사용한다. 내부 `gratitude` 식별자와 JSON category는 이전 백업과 분석 호환을 위해 유지하며 새 표시 이름은 ‘꺼내놓기’다. 이는 구현 판단이며 사용자가 기술 구조를 지정한 것은 아니다.

## 추가로 확인 중인 부분

이야기를 남긴 뒤 사용자가 어떤 반응을 받기를 원하는지 질문했다. 답변을 받기 전에는 상담 대화나 자동 해석, 응답 생성 기능을 추가하지 않는다. 앱이 내용을 이해하거나 사람이 읽었다고 주장하는 표현도 사용하지 않는다. 현재 작업은 이야기를 적는 도중의 제약을 줄이는 데 한정한다.

## 검증

- 200자를 넘는 한글과 여러 문단을 실제 입력해 마지막 문장이 잘리지 않는지 확인한다.
- 앱 화면에서 긴 글 저장 → 수정 → 취소 → 저장된 글 조회와 JSON 백업까지 원문을 보존하는지 확인한다.
- 기본 질문과 사용자 지정 질문, 저장된 질문 스냅샷을 보존하는 기존 테스트를 실행한다.
- 320px/200% 글자와 키보드, 밝은/어두운 테마, 전체 Flutter 테스트와 정적 분석을 확인한다.
- 여러 페이지 PDF에 100개 문단을 출력하고 추출한 텍스트가 순서대로 빠짐없이 남는지, 첫 페이지와 마지막 페이지가 잘리지 않는지 확인한다.
- 변경 범위가 여러 파일에 걸쳐 읽기 전용 교차 검토를 받는다. 배포나 실제 사용자 데이터 수정은 하지 않는다.

## 구현과 검증 결과

위 변경을 반영했다. 첫 질문과 입력 안내를 조정하고, 200자 제한과 입력 카운터를 제거했다. Enter는 다음 질문으로 이동하는 대신 문단을 나눈다. 기존 저장, 수정 취소, 감정만 저장, 책갈피 기능을 유지한다. 입력 칸이 길어지므로 3~8줄 범위에서 늘어난 뒤 내부 스크롤을 사용한다.

- `flutter test --reporter expanded`: 456개 통과. 이후 테스트의 dynamic 타입 접근 경고를 고친 뒤 앱 통합 테스트 9개를 추가로 실행해 통과했다.
- `flutter analyze --no-pub`: No issues found, 종료 코드 0.
- 변경 Dart 파일 포맷 검사와 `git diff --check`: 통과.
- 긴 글 입력 테스트는 변경 전 200자에서 잘리는 실패를 확인한 뒤 변경 후 통과했다. 긴 글 저장, 수정 취소, JSON 내보내기에서 문단과 마지막 문장을 보존했다.
- 긴 PDF 테스트는 변경 전 `TooManyPagesException`을 재현한 뒤 페이지 분할을 수정했다. 관련 6개 테스트 통과. 테스트용 100문단 PDF가 4페이지로 생성됐고, `pdftotext`로 1~100번 문단이 순서대로 한 번씩 포함됐음을 확인했다. 첫 페이지와 마지막 페이지의 렌더링도 확인했다.
- 읽기 전용 교차 검토에서 PDF 분할 문제를 확인했고, 수정 후 추가 지적이 없었다.
- 320px/200% 글자와 키보드 테스트 통과. 실제 앱 위젯 트리에서 390×844 밝은/어두운 테마를 렌더링했다. [밝은 화면](../reviews/assets/2026-11-06-listening-light.png), [어두운 화면](../reviews/assets/2026-11-06-listening-dark.png), [저장 후 화면](../reviews/assets/2026-11-06-listening-saved.png).

화면과 PDF는 가상 기록 및 테스트 DB로 확인했다. 실기기 입력기와 스크린 리더, 실제 사용자의 정서적 경험은 검증하지 않았다. 기존 아이콘/알림 등 다른 작업은 보존했고 배포는 하지 않았다.
