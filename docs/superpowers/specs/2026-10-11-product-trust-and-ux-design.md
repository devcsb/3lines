# 3Lines 기록 신뢰성과 사용 흐름 개선

## 목적과 판단

사용자는 독립적인 기능/UI/UX 검토를 바탕으로 실제 기획과 개선 구현까지 요청했다.
현재 사용자 인터뷰나 완료 시간 실측 근거는 없으므로 연령과 30초 완료율을 검증된
사실로 주장하지 않는다. 우선 사용자는 긴 일기를 지속하기 어렵고 한국어로 짧게
하루를 기록하려는 사람이다. 감정 하나와 답변 한 개로 기록하고, 쉬었다 돌아와도
초안과 과거 기록을 찾으며, 통계와 안내가 실제 저장 내용을 정확하게 설명해야 한다.

기록 보존과 기존 사용 흐름 개선을 선택한다. 새 AI 해석/계정/클라우드/다중 저널은
지금 근거가 부족하다. 메모리 초안만 유지하는 안은 앱 재시작을 해결하지 못하고,
별도 동기화 시스템은 오프라인 앱에 과하다. 기존 SQLite settings에 날짜별 초안을
저장하는 작은 기능을 추가한다. 독립 리뷰의 구체 반례로 우선순위를 정했다.

## 요구사항

### R1 작성 연속성과 날짜

- 초안은 질문, 감정, 답변, 사진과 작성 날짜를 함께 보존한다. 앱 재시작, 질문 변경,
  가져오기, 다른 기록 삭제와 자정 갱신이 미저장 내용을 조용히 지우지 않아야 한다.
- 날짜는 초안에서 고정한다. 자정 뒤 어제 초안을 저장하면 어제 기록에만 적용한다.
  다른 날의 기존 id/date를 섞지 않는다. 어제 초안과 오늘 작성으로 이동하는 선택을
  명시적으로 제공하고 각 날짜의 미완성 내용을 보존한다.
- 작성 중 질문은 스냅샷으로 유지한다. 변경한 질문은 다음 새 기록부터 적용한다.
- 저장 중 입력 변경을 막거나 저장 스냅샷 이후 내용을 유지한다. 저장 성공/취소는
  해당 초안 revision만 정리한다. DB 오류 때 초안과 입력을 남기고 재시도할 수 있다.
- 기존 기록 편집은 원본 snapshot을 비교한다. 가져오기/다른 작업이 원본을 바꾸면
  조용히 덮지 말고 초안을 보존한 채 충돌을 설명한다. 재열기/복사 등 회복 경로가 필요하다.
- 전체 기록 삭제는 영속 초안까지 제거한다. 지연된 자동 보관이 삭제 후 초안을
  되살리지 않아야 한다. 다른 설정은 유지한다. 초안 저장+기록 저장/삭제 경계는
  같은 DB transaction 또는 동등하게 검증한 순서와 revision/epoch로 보호한다.
- 모든 영속 초안의 사진을 시작 정리와 명시 삭제의 참조에 포함한다. 조회/해석 실패는
  기존처럼 보존한다. 실제 사용자 자료가 아닌 임시 File/메모리 DB로 시험한다.

### R2 과거 기록 탐색

- 전체 기록 0건과 선택 기간 0건을 구분한다. 검색과 기간 선택은 도달 가능해야 한다.
  기간 공백은 '이 기간에는 기록이 없어요', 다음 행동은 기간 변경/전체 기록 검색이다.
- 검색 clear는 debounce와 요청을 무효화한다. 늦은 응답은 최신 입력/기간/결과를
  되돌리지 않는다. journal 변경과 새로고침은 선택한 기간과 검색을 유지한다.
- 최근 N일은 오늘 포함 N개 달력 날짜다. Timeline 84/182/365일도 같은 계약이다.
- 상세의 첫/마지막 기록에서 빈 페이지에 머물지 않는다. 인접 조회 실패는 현재
  기록을 유지하고 다시 시도할 수 있다. 스와이프 외 이전/다음 조작도 도달 가능하다.

### R3 통계와 회고의 정직함

- 7/30/90일과 주간 비교는 오늘 포함 정확한 달력 날짜 범위다. 두 비교 주는
  각각 7일이며 겹치지 않는다. 화면/PDF와 repository는 같은 주입 시계를 쓴다.
- 유예는 실제 기록 사이의 하루 공백 한 번만 센다. 오늘 미작성은 어제부터 세며
  어제도 없으면 현재 streak는 0이다. 이력 끝 공백은 유예 사용이 아니다.
- 최장 streak는 겹치는 구간을 포함해 정확히 계산하고 현재값 이상이어야 한다.
  전체 저장 이력의 날짜 컬럼만 읽어 O(n)/상수 추가 메모리로 계산한다. 기존 숨은
  400일/3년 제한은 제거한다. 로컬 마이크로 저널의 실제 일일 행 수에 맞는 비용이다.
- 선택 기간 0건은 감정 0점으로 표시하지 않는다. 기간 내 표본 수/날짜 범위를
  알리고 적은 표본은 지속적 개선이나 최고의 요일로 단정하지 않는다.
- 평균/분포는 완료 기록 한 건부터 제공한다. 주간 차이는 두 7일 구간 각각 기록이
  3일 이상일 때만 표시하고 각 표본 수를 밝힌다. 이는 제품 표시 기준이며 통계적
  유의성 기준으로 부르지 않는다. 요일 표현은 '기록한 날 기준 평균'처럼 서술하고
  '최고의 요일/점점 좋아지는 추세'를 지속적 성향이나 효과로 단정하지 않는다.
- PDF는 월별 목록을 한 번 읽고 그 목록에서 평균/키워드를 함께 계산한다. 오래된
  화면 요약과 최신 본문을 섞지 않는다. 사진 삭제 지연 등의 실제 순서로 시험한다.
- 기간 변경 응답 역전과 journal 갱신은 현재 선택을 보존한다. 숫자 요약은 기록이
  있으면 볼 수 있게 하고 비교 해석만 표본에 맞춰 제한하는 UX를 구현한다.

### R4 부담 적은 작성과 복구

- 예시 추가는 200 grapheme 경계를 넘기지 않는다. 기존 가져오기 장문은 자르지
  않고 줄이거나 유지할 수 있게 한다. 한글 조합/이모지도 실제 입력 기준으로 센다.
- Undo는 삽입 결과가 그대로일 때만 적용하고 이후 입력/다른 예시/저장 뒤 내용을
  지우지 않는다. 빈 답변 삽입에도 같은 정책을 쓴다.
- 회전 질문에는 확인된 맞춤 예시만 제공하고 자유 질문에는 강제 카테고리/예시를
  숨긴다. 예시는 표준 focusable 버튼과 구체적인 접근성 이름을 사용한다.
- 질문 편집은 공백 오류를 필드에 보여주고 저장 완료까지 기다린다. 실패하면
  입력을 유지하고 재시도한다. 느린 저장의 중복 제출을 막는다.
- 사진 선택 취소는 조용히 끝내되 권한/복사 실패를 구분해 다시 시도할 안내를
  보여준다. 사진이 없어도 텍스트를 이어 쓸 수 있다. 인증 취소/실패에도 실제
  기기 인증 재시도 안내를 제공하고 존재하지 않는 복구 수단을 약속하지 않는다.

### R5 알림과 보관 안내

- '매일 리마인더'는 사용자가 선택한 시각의 하루 한 번 알림이다. 별도 opt-in 없는
  스트릭 위험/일요일 회고 알림은 제거하고 기존 예약도 정리한다. 저장한 날은
  건너뛰고 다음 미작성 날의 일일 예약을 유지한다. 권한 거부와 보상 복구를 보존한다.
- 카피는 '오늘 마음을 짧게 남겨볼까요?'처럼 중립적으로 쓴다. 회복탄력성 향상이나
  감정 개선을 검증된 제품 효과처럼 말하지 않는다. 한 줄부터 시작하도록 안내한다.
- 기록 보관 안내는 자체 서버 전송 없음, 앱 삭제/기기 분실 대비 텍스트 내보내기,
  JSON 평문/사진·설정 미포함, 앱 잠금의 앱 진입 보호 범위를 설명한다. OS 백업이나
  암호화되지 않은 저장을 '완전한 프라이버시/기기에만'으로 절대 보장하지 않는다.

### R6 시각 품질과 베타 진입

- Sage 분위기를 유지하면서 일반 텍스트 4.5:1, 의미 있는 아이콘 3:1을 테마별로
  확인한다. 장식 색을 정보 텍스트 색으로 강제하지 않는다. native controls와
  48dp 터치 영역을 쓰고 큰 글씨를 축소하지 않는다.
- 온보딩은 320×640/640×320, 200% 글씨와 reduce motion에서 각 페이지와 시작
  버튼을 조작할 수 있어야 한다. 현재 페이지를 텍스트/semantics로 알린다.
- 기본 Flutter launcher icon과 Android 'three_lines' 표시 이름을 3Lines 식별로
  바꾼다. 작은 크기에 읽히는 Sage/세 줄 모티프를 사용한다. 불필요한 장식은 늘리지 않는다.
- GitHub Android 베타의 실제 설치 경로와 README 약속을 일치시킨다. 서명 APK 생성,
  검증과 첨부가 pipeline에 포함되어야 한다. 외부 게시 없이 코드/로컬 빌드 가능한
  범위를 검증하고 실제 배포 여부는 현재 외부 상태를 따로 확인한다.
- 타깃/30초 완료/심리 효과를 검증 사실로 만들지 않는다. 첫 기록, 쉰 뒤 재방문,
  초안 복구와 텍스트 복원의 베타 관찰 시나리오와 명확한 분모를 둔 지표를 문서화한다.
  새 네트워크 추적은 추가하지 않는다.

## 검증과 완료

구현은 gpt-6.1-sol medium, 독립 검토는 별도 컨텍스트 gpt-6.1-sol xhigh가 맡는다.
실행자는 소유 파일만 편집하며 Git과 전체 gate는 root가 관리한다. 실제 실패 반례에
대한 시험을 먼저 고정하고, 타깃 시험 뒤 source review를 받는다. 시각 변경은
실제 Flutter 렌더를 확인한다. 전체 analyze/test와 가능한 Android 빌드를 마지막에
실행하고 R1~R6 각각의 근거를 completion matrix에 남긴다. 실기기/OS 알림 도착은
호스트 시험과 구분하며 미검증을 완료 근거로 쓰지 않는다.
