# Frictionless Calm UX 고도화 PRD

## 문서 정보

- 버전: 1.0
- 작성일: 2026-08-28
- 상태: 구현 전 설계안
- 대상 릴리스: 3Lines UX 고도화 루프 (스토어 버전은 별도 릴리스 게이트에서 결정)
- 기준 브랜치: `codex/runtime-correctness-energy`

## 1. 한 줄 요약

3Lines의 핵심 차별점인 “하루 3줄, 30초”를 유지하면서 입력·저장·탭 전환의 인지적 마찰을 줄이고, 짧고 목적이 분명한 모션으로 기록 완료감을 전달한다. 감정 명명·자기연민·구체적 의도 계획은 진단이나 치료가 아닌 선택적 자기성찰 도구로만 제공하며, 스트릭 실패감과 알림 피로를 만들지 않는다.

## 2. 문제 정의

현재 앱은 핵심 기록·감정·회고 기능과 접근성 기반을 갖췄지만 다음 경험이 분리되어 있다.

1. 하단 탭 전환은 상태를 보존하는 대신 화면이 즉시 교체되어 공간적 연속성이 약하다.
2. 저장 완료 이펙트는 시각적 축하에 집중되어 있으며, 스크린 리더가 명확히 닫거나 다음 작업으로 이동할 수 있는 의미 구조가 부족하다.
3. 질문·감정·회고가 각각 좋은 기능이지만 “지금 무엇을 하면 되는지”와 “다음에 무엇을 할지”가 한 흐름으로 연결되지 않는다.
4. 일일 질문 회전·기록 날짜·위젯 날짜는 사용자의 현지 달력 경계를 따라야 한다. UTC timestamp나 DST에 의존한 동작은 기록 의미를 흔든다.
5. 스트릭·배지·반복 알림은 재방문을 돕지만, 놓친 날을 실패로 강조하면 자기관리 앱의 정서적 안전성과 충돌할 수 있다.

## 3. 제품 원칙

### 3.1 사용성 원칙

- **첫 입력까지 한 화면**: 앱을 열고 질문을 읽은 뒤 바로 입력할 수 있어야 한다.
- **진행 중인 작업은 사라지지 않음**: 탭 이동·백그라운드·키보드 전환 후에도 작성 중인 답변은 유지한다.
- **완료보다 회복을 우선**: 기록을 놓친 날에는 “끊겼다”보다 “오늘 다시 시작”을 먼저 보여준다.
- **짧고 취소 가능한 모션**: 애니메이션은 상태·인과관계를 설명할 때만 사용하며 사용자의 다음 탭을 막지 않는다.
- **시각 효과는 의미를 대체하지 않음**: 선택 상태·저장 성공·오류는 텍스트와 Semantics로도 전달한다.

### 3.2 안전·개인정보 원칙

- 3Lines는 자기성찰·웰빙 도구이지 진단·치료·위기 대응 서비스가 아니다.
- 점수·스트릭·키워드로 우울증, 불안장애, 자살 위험 등을 추론하거나 표시하지 않는다.
- 알림 본문에는 저널 원문을 넣지 않는다. 기기 잠금 화면·웨어러블·미러링에서도 중립 문구를 유지한다.
- 서버·광고·외부 분석 SDK 없이 로컬 저장 정책을 유지한다. 사용성 측정은 테스트와 사용자가 볼 수 있는 로컬 요약 범위로 제한한다.
- 사용자가 힘든 감정을 선택해도 과도한 긍정 문구를 강요하지 않는다. “괜찮아야 한다”보다 감정의 존재를 인정하는 문구를 사용한다.

### 4.2 심리·정신건강 근거와 한계

- 표현적 글쓰기의 장기 추적 메타분석은 우울·불안·스트레스 감소 효과가 작지만 유의했고, 1–3일의 짧은 간격에서 더 강한 효과가 관찰됐다. 따라서 30초 기록은 짧고 반복 가능한 루프로 설계하되 치료 효과를 약속하지 않는다 ([Guo et al., 2023](https://pubmed.ncbi.nlm.nih.gov/36536513/)).
- 감사 개입은 웰빙에 작고 일관된 긍정 효과를 보였으나 연구 간 이질성과 편향이 있다. 감사 질문을 의무화하거나 힘든 감정을 덮는 용도로 사용하지 않는다 ([Cregg et al., 2023](https://pubmed.ncbi.nlm.nih.gov/37585888/), [Boggiss et al., 2020](https://pubmed.ncbi.nlm.nih.gov/32590219/)).
- 자기연민 개입은 우울·불안·스트레스에 작거나 중간 정도 효과를 보였지만 포함 연구의 전반적 편향 위험이 높다. “자기연민 문구”는 선택형 보조 피드백으로만 제공한다 ([Han & Kim, 2023](https://pubmed.ncbi.nlm.nih.gov/37362192/)).
- 감정 명명(affect labeling)은 강한 부정 자극에서 distress를 낮출 수 있지만 낮은 강도의 감정에서는 오히려 주의가 필요하다는 결과도 있다. 점수 1–5를 임상적 상태로 해석하지 않고, 사용자가 선택한 단어를 그대로 존중한다 ([Levy-Gigi & Shamay-Tsoory, 2023](https://pubmed.ncbi.nlm.nih.gov/36580454/)).
- if–then 형태의 implementation intention은 목표 달성에 도움을 줄 수 있다는 메타분석이 있으므로, “내일 내가 되고 싶은 모습”을 선택적으로 “상황–작은 행동”으로 구체화할 수 있다 ([Toli et al., 2016](https://pubmed.ncbi.nlm.nih.gov/25965276/)).
- 습관 형성 시간은 개인차가 매우 크며 연구에서 중앙값 59–66일, 평균 106–154일로 보고됐다. 7일/30일 스트릭을 건강이나 의지의 척도로 표시하지 않는다 ([Time to Form a Habit, 2024](https://pubmed.ncbi.nlm.nih.gov/39685110/)).
- 건강·웰빙 게이미피케이션의 효과는 긍정·혼합 결과가 모두 있으며 연구 품질도 다양하다. 포인트·리더보드보다 자기 모니터링과 과거의 성공을 부드럽게 피드백한다 ([Johnson et al., 2016](https://pubmed.ncbi.nlm.nih.gov/30135818/), [Cheng et al., 2019](https://pubmed.ncbi.nlm.nih.gov/31244479/)).
- 디지털 정신건강 개입의 참여를 높이는 전략은 알림·개인화·코칭 등에서 효과가 혼합되어 있고, 개인화 부족·기술 문제·높은 부담은 이탈과 연결될 수 있다. 모바일 반복 측정 연구에서도 스트레스·우울한 기분이 당일 부담과 비순응에 연결됐다. 알림 빈도와 작성량을 늘리는 것이 목표가 아니다 ([Borghouts et al., 2021](https://pubmed.ncbi.nlm.nih.gov/33759801/), [Tate et al., 2024](https://pubmed.ncbi.nlm.nih.gov/38656787/)).
- 디지털 정신건강 서비스는 증상 악화 등 안전 사건을 능동적으로 수집하고 완화해야 한다. 3Lines는 치료 서비스가 아니므로 진단·위기 개입을 흉내 내지 않고, 관련 기능을 추가할 때 별도의 임상·안전 검토를 거친다 ([Taher et al., 2023](https://pubmed.ncbi.nlm.nih.gov/37812471/), [WHO psychological self-help guidance](https://www.who.int/publications/i/item/9789240120785)).

## 7. 경험 설계

### 7.1 Today: 기록 시작

1. 앱 진입 시 날짜와 짧은 인사말을 먼저 보여준다.
2. 감정 선택은 5단계 원형 버튼으로 유지하되, 선택 즉시 라벨과 짧은 비판단적 피드백을 제공한다.
3. 세 질문은 작성 당시 스냅샷을 보존한다. 새 질문 설정은 다음 기록부터 적용한다.
4. 답변이 비어 있을 때 제안 문구를 선택적으로 삽입한다. 기존 답변은 덮어쓰지 않으며 한 번의 되돌리기를 제공한다.
5. 최소 감정 또는 한 답변이면 저장 가능 상태를 명확히 표시한다. 3줄 모두 작성하도록 강제하지 않는다.

### 7.2 저장 완료와 회복

- 저장 버튼은 탭 즉시 busy semantics를 제공하고 중복 저장을 막는다.
- 성공 시 체크·색상·짧은 문구로 500–600ms 이내 피드백을 제공한다.
- 파티클·탄성 효과는 장식이며 reduce motion에서는 제거한다.
- 완료 화면은 자동으로 닫히며, 항상 명시적인 “닫기/계속” 의미를 제공한다. 사용자는 애니메이션을 기다리지 않고 탭할 수 있다.
- 이전 날짜를 놓친 경우 “기록을 잃었다”는 표현 대신 “오늘 다시 시작” CTA와 grace-day 상태를 제공한다.

### 7.3 화면 전환

- 하단 탭은 상태를 보존하는 IndexedStack을 유지한다. 인덱스가 바뀐 뒤 활성 브랜치 컨테이너만 240ms fade-through로 전환한다.
- GlobalKey 중복을 피하기 위해 이전·새 shell을 동시에 트리에 두지 않고, 브랜치 교체 후 opacity/offset만 애니메이션한다.
- 온보딩·상세 BottomSheet·탭 전환은 동일한 easing 방향을 사용한다.
- 화면 이탈·dispose 시 모든 controller/timer를 정리한다.

### 7.4 Insights: 회고의 한 화면 연결

- 기간 선택 후 기존 차트 위치는 유지하고 값·카드만 보간한다.
- 7일 미만 사용자는 잠금보다 “몇 번 더 기록하면 무엇을 볼 수 있는지”를 설명한다.
- 7일 이상 사용자는 감정 추이, 반복 키워드, 주간 회고, 다음 주의 작은 의도를 한 흐름으로 보여준다.
- 데이터가 없는 경우 빈 차트보다 다음 기록을 시작하는 CTA를 우선한다.

## 8. 모션·접근성 명세

### 모션 토큰

| 토큰 | 값 | 사용처 |
|---|---:|---|
| `instant` | 0ms | reduce motion 최종 상태, 데이터 즉시 반영 |
| `micro` | 120ms | 탭 색상·scale·focus feedback |
| `standard` | 240ms | 탭 전환·카드 상태·fade-through |
| `entrance` | 360ms | 최초 화면/섹션 진입 |
| `celebration` | 600ms 이하 | 저장 완료의 의미 전달 |

- 기본 curve는 `easeOutCubic` 또는 Material 기본 easing을 사용한다.
- 반복되는 입력 컨트롤에는 장식 애니메이션을 추가하지 않는다.
- `MediaQuery.disableAnimationsOf(context)`가 true이면 이동·확대·파티클·stagger delay를 fade 또는 색상 변화로 대체한다.
- 모든 모션은 사용자의 다음 입력을 차단하지 않는다.

### 접근성 수용 기준

- 커스텀 탭 컨트롤의 실제 hit target은 최소 48dp(Android)·44pt(iOS) 이상이다.
- 선택·활성·비활성·오류 상태가 색상 이외의 label/state로 노출된다.
- 200% 텍스트 크기에서 핵심 Today/Timeline/Insights 업무가 스크롤과 줄바꿈으로 완료된다.
- VoiceOver/TalkBack이 저장 완료, 히트맵 셀, 기간 선택, 사진 추가를 의미 있게 읽고 활성화할 수 있다.

## 10. 비기능 요구사항

- 새 기능은 네트워크·상시 polling·무한 animation을 추가하지 않는다.
- Flutter 단위/위젯 테스트, `dart analyze`, 포맷 검사를 통과한다.
- reduce motion·큰 글자·다크모드·저사양 기기에서 성능 저하가 없어야 한다.
- 알림·위젯·내보내기·생체 잠금 등 기존 계약을 변경할 경우 별도 회귀 테스트를 추가한다.
- 화면 전환 중 프레임 드롭은 연결된 실기기에서 profile 모드로 확인하고, 호스트 테스트 통과를 60fps 증거로 과장하지 않는다.

## 11. KPI 및 평가 방법

프라이버시 정책상 외부 분석 SDK를 넣지 않는다. 개발·베타 검증에서는 테스트 하네스와 사용성 세션으로 다음을 확인한다.

| 지표 | 목표 | 측정 방법 |
|---|---:|---|
| 첫 입력까지 시간 | 중앙값 5초 이하 | Today 진입부터 첫 TextField focus 이벤트 |
| 첫 기록 완료 시간 | 중앙값 45초 이하 | Today 진입부터 성공 저장까지 |
| 저장 후 다음 조작 가능 | 600ms 이내 | 완료 피드백 중 탭/닫기 동작 테스트 |
| 빈 날 회복 성공 | 1 CTA | 회복 상태에서 Today 입력 화면까지 탭 1회 |
| 접근성 완료율 | 핵심 흐름 100% | 200% text, reduce motion, semantics 위젯 테스트 + 실기기 수동 테스트 |
| 알림 중단률 | 악화 없음 | 베타에서 권한 거부·일시중지·재활성화 경로의 사용자 피드백 |

KPI는 건강 상태의 개선이나 임상 효과를 의미하지 않는다. 지속성 지표는 사용자 선택과 정서적 안전성의 맥락에서 해석한다.

## 12. 단계별 구현 순서

1. Motion token과 reduce-motion helper를 추가하고 기존 `StaggeredFadeIn`, 핵심 입력 피드백, 완료 애니메이션, 차트 갱신에 적용한다.
2. `ScaffoldWithNavBar`를 상태 보존형 fade-through 컨테이너로 교체하고 GlobalKey·dispose·접근성 회귀 테스트를 추가한다.
3. `CompletionAnimation`에 명시적 Semantics 닫기 동작과 중립 완료 문구를 추가하고, 자동 종료·탭 종료·reduce motion을 테스트한다.
4. Today/Insights 회복 CTA와 빈 상태 문구를 정리한다. 데이터·알림 계약을 변경하지 않는다.
5. 실제 Android/iOS 기기에서 reduce motion, 200% 글자, VoiceOver/TalkBack, 탭 전환 프레임, 알림·위젯 경계 시나리오를 측정한다.

## 13. 출시 전 안전 체크리스트

- 서명·프로비저닝·CocoaPods 등 운영 차단 게이트는 별도 릴리스 체크리스트에서 관리한다.
- 이번 PRD 구현만으로 정신건강 치료·예방 효과를 주장하지 않는다.
- 위기 대응·자살 위험 감지 기능을 추가하려면 임상 자문, 지역별 연락처 검증, 안전성 평가, 개인정보 영향평가를 별도 수행한다.
- 알림 문구·스크린샷·스토어 설명이 실제 중립 개인정보 정책과 일치하는지 확인한다.
