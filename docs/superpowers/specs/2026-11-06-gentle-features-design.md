# 글을 쓰기 어려운 날과 다시 읽고 싶은 날을 잇는 기능

2026-11-06. 사용자는 경쟁 기능 중 3Lines와 결합 효과가 큰 것을 판단해 설계와 구현까지 요청했다. 별도 우선순위 답변이 없어 앞선 ‘힘든 날에도 부담 없이 마음을 남기는 경험’을 기준으로 범위를 정했다.

## 경쟁 기능과 선택

| 공식 근거 | 현재 3Lines | 판단 |
|---|---|---|
| [Daylio](https://daylio.net/)는 글 없이 감정과 활동을 선택하는 기록을 제공한다. | 감정과 최소 한 답변이 필요하다. | **감정만 기록하기 채택.** 입력할 여력이 없을 때도 기존 감정 달력과 회고에 연결된다. 별도 모드나 추가 질문 없이 쓸 수 있다. |
| [Day One Favorite entries](https://dayoneapp.com/guides/tips-and-tutorials/favorite-entries/)는 사용자가 표시한 기록을 따로 찾아보게 한다. | 날짜와 검색으로만 기록을 다시 찾는다. | **책갈피와 모아보기 채택.** 자동 추천 없이 사용자가 다시 읽고 싶은 내용을 선택한다. 힘든 기록도 선택할 수 있으며 ‘좋았던 날’로 분류하지 않는다. |

| [Daylio](https://daylio.net/)의 목표와 활동 추적 | 짧은 저널과 기본 감정 통계에 집중한다. | 목표 경쟁과 입력 항목 증가는 현재의 부담 감소 방향과 맞지 않아 제외한다. |

검색, 사진, 로컬 잠금, 알림, 감정 달력, JSON 가져오기/내보내기는 이미 있으므로 중복 구현하지 않는다. 이 비교는 공식 문서에서 확인한 기능과 코드 조사에 근거한다. 시너지와 부담 감소는 제품 설계 판단이며 실사용 효과를 측정한 결과는 아니다.

## 1. 감정만 기록하기

- 감정 1–5 중 하나를 선택하면 답변이 없어도 저장할 수 있다. 감정 미선택 저장은 여전히 금지한다.
- 답변이 모두 공백이면 버튼은 ‘마음만 남기기’, 안내는 ‘글이 떠오르지 않는 날엔 감정만 남겨도 괜찮아요’다. 글이 있으면 기존 ‘이만큼 저장하기’를 유지한다.
- 저장은 명시적 버튼 동작으로만 수행한다. 감정을 탭했다는 이유만으로 기록을 생성하지 않는다.
- 감정만 기록한 상태에서는 Today와 상세에서 빈 답변 카드 세 개를 나열하지 않고 Today에서는 ‘마음만 남긴 기록이에요. 원하면 글을 더할 수 있어요’, 과거 기록도 여는 상세에서는 ‘마음만 남긴 기록이에요’를 보여준다. Today 수정 기능으로 같은 날짜의 기록에 글을 추가할 수 있다.
- 감정만 기록한 날도 기존 달력, 기록 수, 통계, 알림 종료, 위젯에 한 개의 정상 기록으로 반영한다. 텍스트 키워드 추출에는 빈 답변이므로 단어가 추가되지 않는다.
- JSON은 기존 세 질문/빈 답변과 감정 형식을 사용한다. 새 기록 타입이나 스키마가 필요하지 않다.

## 2. 책갈피

- 오늘 저장한 기록과 날짜별 상세에 ‘책갈피에 담기’/‘책갈피 해제’ 버튼을 둔다. 기록 전체에 적용하며 개인적인 의미를 앱이 추정하지 않는다.
- 타임라인에서 ‘책갈피 모아보기’로 전용 화면을 연다. 최근 12주에 기록이 없어도 진입할 수 있다. 모든 책갈피를 날짜 내림차순으로 표시하고 긴 목록은 ListView.builder로 지연 렌더링한다.
- 각 항목은 날짜, 사용자가 선택한 감정 이름, 답변 요약을 보여준다. 감정만 기록한 경우 ‘마음만 남긴 기록’이라고 표시한다. 빈 상태와 불러오기 실패에도 다음 행동을 안내한다.
- 책갈피에서 연 상세는 해당 기록만 보여준다. 전체 저널의 이전/다음 날로 스와이프하지 않는다. 기존 타임라인 상세 탐색은 유지한다.
- 추가/해제 중 같은 버튼 중복 입력을 막고, DB 반영 전 성공으로 표시하지 않는다. 실패하면 상태를 보존하고 재시도할 수 있다. 삭제된 기록을 다시 생성하지 않는다.

## 저장과 호환성

- Drift `entries`에 `isBookmarked` boolean(default false)을 추가하고 schemaVersion을 2에서 3으로 올린다. v1→v2 사진 열 추가 경로를 보존하고 v1/v2→v3에서 기본 false를 적용한다. 실제 사용자 DB나 운영 환경에는 이 작업 중 직접 마이그레이션하지 않는다.
- `DailyEntry`의 생성자, copyWith, 동등성, hashCode와 JSON에 `isBookmarked`/`is_bookmarked`를 반영한다.
- 일반 일기 저장의 날짜 충돌 업데이트는 기존 책갈피를 유지한다. 책갈피 변경은 해당 boolean만 갱신해 답변과 작성 시각을 바꾸지 않는다.
- JSON 내보내기는 책갈피를 포함한다. 가져오기는 명시적인 boolean이면 반영하고, 필드가 없는 이전 백업은 신규 기록에서 false, 기존 기록에서는 현재 책갈피를 유지한다. boolean 이외의 값은 해당 항목을 건너뛴다. 기존 가져오기 트랜잭션을 재사용한다.
- 단건/전체 삭제는 같은 entries 행을 삭제하므로 책갈피도 함께 사라진다. 별도 고아 메타데이터를 만들지 않는다.
- 조회는 기존 DB 스트림을 사용한다. 책갈피 변경이 저널 내용 변경 이벤트를 발생시켜 작성 중인 Today를 새로고침하거나 초안을 날리지 않게 한다.

## 검증

1. 감정만 명시적으로 저장, 텍스트 추가 후 재저장, 실패 시 입력 보존, 공백 답변, 감정 미선택 거절.
2. 현재/이전 날짜 기록의 책갈피 추가와 해제, 재조회, 삭제와 전체 삭제, 일반 수정 후 유지, 책갈피가 없는 오래된 백업 덮어쓰기.
3. v1/v2 DB 업그레이드 후 기록/사진/책갈피 기본값 보존. 새 DB 생성도 검증.
4. 책갈피 JSON 왕복, 잘못된 필드 타입 건너뛰기, 감정만 기록의 왕복.
5. 타임라인 → 모아보기 → 상세 → 해제의 실제 앱 경로. 오래된 책갈피, 빈 목록, 동시/중복 탭, 200% 글자와 작은 화면.
6. 기존 전체 Flutter 테스트와 정적 분석. 실기기 접근성과 실제 사용자 만족도는 별도 검증으로 남긴다.
