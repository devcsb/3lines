# 부담을 낮추는 3Lines 기록 경험

작성일 2026-11-06. 현재 Flutter 앱을 대상으로 한 리서치와 구현 설계다. 치료 효과나 실제 사용자 검증 결과를 주장하지 않는다.

## 조사와 해석

UI/UX Pro Max의 디자인 시스템 검색은 웹 랜딩 페이지와 파란색 CTA를 제안해 이 앱에 맞지 않았다. 이를 채택하지 않고 기존 세이지 테마를 유지한다. Flutter 검색에서 확인한 Semantics와 TextScaler 지침은 적용한다.

## 현재 문제

- 쓰기 전에 명언, 연속 기록, 기념 배너, 과거 기록을 지나야 한다.
- 한 답변으로 저장할 수 있지만 0/3 진행 링이 세 답변을 목표처럼 보이게 한다.
- 낮은 감정에도 전면 축하 화면과 연속 기록을 자동 표시한다.
- 감정 라벨은 10–11px 반투명 텍스트다. 선택 시 크기가 바뀌고 의미를 색상에 의존한다.
- 질문과 예시는 감사, 성장, 극복을 전제한다. 사용자가 아무 교훈도 찾지 못한 날을 담기 어렵다.

## 채택한 경험

1. 날짜 → ‘지금의 나에게, 한 줄’ → ‘세 질문 중 편한 것 하나만 적어도 괜찮아요’ → 감정 → 세 질문 → 선택형 사진 → 선택형 회고.
2. 기본 질문은 작은 순간, 현재 마음, 필요한 돌봄을 담는다. 질문은 도움말일 뿐이며 다른 이야기를 써도 된다고 안내한다. 기존 저장된 질문 스냅샷과 사용자 설정은 보존한다.
3. 감정은 기존 5개 값과 저장 계약을 유지한다. 이름을 읽기 쉽게 표시하고, 선택 표시를 모양과 semantics로도 전달한다. 모든 감정을 같은 시각적 무게로 다룬다. 강제 긍정이나 점수 판정을 추가하지 않는다.
4. 예시는 질문별로 접는다. 직접 펼쳐 고를 수 있고, 입력된 글을 덮어쓰지 않는다. 사용자 지정 질문에는 기본 카테고리 예시를 붙이지 않는다.
5. 작성량 분수와 진행 링을 제거한다. 버튼 이름은 ‘이만큼 저장하기’, 저장 조건은 별도 안내한다. 기존 중복 저장 방지와 수정 취소를 유지한다.
6. 저장하면 같은 화면에서 ‘기록을 저장했어요’를 알린다. 임의 시간 후 사라지는 전면 축하를 띄우지 않는다. 실패하면 내용이 남으며 재시도할 수 있다.
7. 지난 기록, 감정 흐름, 연속 기록, 기념 배너는 아래의 ‘지난 기록 돌아보기’를 열 때만 보여준다. 회고 내용은 기본 상태의 접근성 트리에도 노출하지 않는다.
8. 첫 안내에서도 30초 제한처럼 느낄 수 있는 문구와 3줄 의무를 없앤다. 본문 줄간격, 읽을 수 있는 대비, 충분한 여백, 48px 버튼, 200% 글자, 동작 줄이기를 유지한다.

## 이번 범위 밖

DB 변경, 감정 미선택 저장, 임상 판단, 감정 자동 분석, 위기 감지, 알림 정책 변경, 스트릭 계산 변경, 스토어 배포. 초안 영구 저장도 추가하지 않으므로 앱을 닫아도 보존된다고 안내하지 않는다. Timeline/Insights의 분석 화면은 유지한다.

## 검증과 후속 사용자 조사

- 실제 DB를 사용하는 앱 흐름 테스트로 한 답변 저장과 수정, 실패 시 입력 보존을 확인한다.
- 위젯 테스트로 회고의 명시적 열기, 예시의 키보드/접근성 동작, 작은 화면과 200% 글자, 다크 모드, 저장 semantics를 확인한다.
- 실제 화면을 이미지로 렌더링해 대비와 줄바꿈을 확인한다.
- 후속 사용성 세션에서는 ‘쓰지 않고 나가도 괜찮다고 느꼈는지’, ‘저장된 시점이 분명했는지’, ‘문구가 감정을 대신 판단했는지’를 묻는다. 민감한 개인 경험을 설명하도록 요구하지 않는다. 이 작업에서는 해당 사용자 세션을 진행하지 않는다.
